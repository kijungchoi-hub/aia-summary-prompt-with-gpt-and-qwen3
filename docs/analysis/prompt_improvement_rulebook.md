# 프롬프트 개선 항목 룰북

## 목적

`data/origin/stt_summary_20260311_170910.csv`에 추가한 `프롬프트개선항목` 컬럼을 공통 규칙 세트로 정리한 문서다.
반복 오류를 케이스별 메모가 아니라 재사용 가능한 프롬프트 규칙으로 승격하는 데 목적이 있다.

## 공통 기본 규칙

- 고객 요청 사항을 첫 줄에 배치한다.
- 처리 상태와 상담사 후속조치를 분리해서 쓴다.
- 원문에 없는 확장 서술은 금지한다.
- 정답지 기준 비핵심 STT 부가정보 추가를 억제한다.
- 고객명, 생년월일, 주소, 연락처, 카드번호 등 개인정보는 제외한다.

## 오류 유형별 규칙

### 1. 정보 누락

- 정답지 기준 필수 항목 누락 점검을 강화한다.
- 고객 요청 사항, 처리 상태, 상담사 후속조치를 별도 항목으로 점검한다.
- 상담사 후속조치, 콜백, 문자발송, 재문의 안내 누락을 금지한다.
- 고객 문의 목적을 첫 줄에 명시하고 배경 설명보다 우선 요약한다.

### 2. 해석 오류

- 원문 표현 기준으로 맥락과 상태를 보수적으로 해석한다.
- 처리 상태와 완료 여부는 원문 표현 그대로 유지한다.
- 철회, 반송, 해지, 접수, 유지 상태를 서로 바꿔 쓰지 않는다.
- 계약자, 피보험자, 배우자, 문의 주체 관계를 별도 항목으로 명시한다.

### 3. 사실 오류

- 원문과 정답지 교차검증으로 사실관계 반전을 방지한다.
- 상태값, 일정, 수치, 가능 여부는 원문 확인 후에만 쓴다.
- 확인 불가 내용을 확인됨으로 바꾸지 않는다.

### 4. 환각 오류

- 원문 근거 없는 추정 문장을 금지한다.
- 불확실하면 제외한다.
- 오전사 또는 혼입 의심 표현은 보수적으로 제거한다.

### 5. STT 내용 추가(정상)

- 정답지 기준 비핵심 STT 부가정보 추가를 억제한다.
- 핵심 업무 목적과 직접 무관한 상세 금액, 날짜, 신상 정보는 제외한다.
- 원문에 있더라도 정답지와 업무 목적상 불필요하면 쓰지 않는다.

### 6. STT 내용 추가(오전사)

- 오전사 의심 표현은 문맥 검증 후 불확실하면 제외한다.
- 발화 오류, 잘못 인식된 단어, 잘못 들린 날짜와 코드값은 그대로 요약하지 않는다.

## 관계/주체 규칙

- 계약자 본인 확인, 문의 주체, 피보험자, 보장 대상을 분리 해석한다.
- 고객이 본인 계약을 지정하면 이후 요약은 해당 계약 기준으로 고정한다.
- 계약자 본인 확인 발화만으로 고객을 피보험자 또는 보장 대상 당사자로 단정하지 않는다.
- 배우자, 자녀, 다른 피보험자 계약이 함께 언급되면 누구 계약인지 별도 항목으로 적는다.

### 대표 사례

- 케이스 13: 고객은 본인 계약 보장 내용을 문의했지만 generated는 다른 피보험자 계약으로 서술했다.
- 이 유형에서는 `본인 계약 보장 문의`와 `실제 진단/수술 당사자`를 구분해야 한다.

## 상태 규칙

- 완료와 진행 중을 섞지 않는다.
- 철회와 반송을 섞지 않는다.
- 정상 유지, 해지, 미납, 완납 상태를 임의로 완화하거나 확정하지 않는다.

## 후속조치 규칙

- 상담사 후속조치, 문자 발송, 콜백, 전달, 재문의 안내는 별도 항목으로 유지한다.
- 고객 요청과 후속조치를 한 문장에 뭉개지 않는다.

## 불필요 정보 억제 규칙

- 개인정보 제외
- 비핵심 세부 금액과 상세 시각 제외
- 정답지에 없는 배경 설명, 인사말, 공감 멘트 제외

## 권장 적용 순서

1. 고객 요청 사항 추출
2. 계약자/피보험자/문의 주체 관계 확정
3. 처리 상태 확인
4. 상담사 후속조치 확인
5. 정답지 기준 비핵심 STT 추가 제거
6. 오전사, 혼입, 환각 위험 문장 제거
