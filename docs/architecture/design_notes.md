# 설계 노트

## 왜 두 입력을 분리하는가

`llm_analysis`와 `customer_feedback`를 하나로 합치면 다음 문제가 생깁니다.

1. 모델이 개선 근거와 현업 요구를 구분하지 못한다.
2. 실험 시 어떤 변경이 품질에 영향을 줬는지 추적하기 어렵다.
3. 고객 피드백이 단건 의견인지 반복 패턴인지 관리하기 어렵다.

따라서 두 입력은 분리하고, 프롬프트에서 역할을 다르게 선언하는 편이 안전합니다.

## 권장 데이터 정의

- `llm_analysis`: 모델 평가 또는 judge 결과에서 도출한 개선 포인트
- `customer_feedback`: 현업 검토자가 실제 업무 관점에서 요구한 포함/제외/표현 선호

## 반영 우선순위

1. 정책, 보안, 컴플라이언스
2. 원문에서 직접 확인 가능한 사실
3. 반복적으로 누적된 고객 피드백
4. LLM 분석 기반 구조 개선
5. 단건 표현 선호

## 운영 팁

1. `customer_feedback.must_include`는 단건 코멘트보다 누적 빈도 기준으로 관리하는 것이 좋습니다.
2. `preferred_labels`는 현업 화면 문구와 맞추면 검수 속도가 빨라집니다.
3. `llm_analysis.missing_points`는 judge 결과에서 자동 추출하도록 연결하면 반복 개선 루프를 만들기 쉽습니다.
4. 동일 상담 유형별로 `priority_topics` 템플릿을 따로 두면 도메인 적합성이 더 올라갑니다.
