# 고정/가변/학습 레이어 분리안

## 목적

프롬프트를 계속 수정하는 방식 대신,
변경 빈도와 책임 범위에 따라 규칙을 3개 레이어로 분리한다.

## 1. 고정 레이어

거의 바뀌지 않는 절대 규칙이다.

포함 항목:

- 원문 외 내용 생성 금지
- 개인정보 제외 또는 마스킹
- 추정, 단정, 책임 판단 금지
- 출력 형식 고정
- 컴플라이언스 관련 표현 제한

특징:

- 모델이 바뀌어도 유지된다.
- 가장 짧고 단단해야 한다.
- 실험으로 쉽게 건드리지 않는다.

예시 문장:

```text
요약의 모든 내용은 원문에서 직접 확인 가능한 사실만 사용한다.
원문에 없는 정보는 추론하여 추가하지 않는다.
출력은 지정된 섹션과 순서를 반드시 따른다.
```

## 2. 가변 레이어

상담 유형, 업무 목적, 채널별로 달라지는 규칙이다.

포함 항목:

- 보험금 청구 상담에서 필요한 필수 항목
- 민원 상담에서 우선 다뤄야 할 항목
- 계약 변경 상담에서 필요한 관계 정보
- 요약 대상이 고객 기준인지 상담사 기준인지

특징:

- 업무 유형별 템플릿으로 관리한다.
- 프롬프트 본문보다 설정값 형태가 더 적합하다.
- 상담 유형이 바뀌면 이 레이어만 교체한다.

예시:

```json
{
  "consult_type": "보험금청구",
  "required_sections": [
    "고객 요청 사항",
    "처리 상태",
    "기한/긴급성",
    "민원/불만"
  ]
}
```

## 3. 학습 레이어

평가 결과와 현업 피드백을 반영하며 자주 조정되는 규칙이다.

포함 항목:

- 자주 누락되는 항목
- 불필요하게 반복되는 표현
- 현업이 싫어하는 문구
- 선호 라벨명
- 최근 평가에서 낮은 점수를 받은 포인트

특징:

- 가장 자주 바뀐다.
- 프롬프트 본문에 직접 누적하지 않는다.
- 룰 데이터나 힌트 데이터로 외부 관리한다.

예시:

```json
{
  "must_include": [
    "계약자/피보험자 관계",
    "불만 사유"
  ],
  "suggested_focus": [
    "고객 요청을 첫 줄에 배치"
  ]
}
```

## 레이어별 변경 원칙

1. 고정 레이어는 정책 변경이 아닌 한 수정하지 않는다.
2. 가변 레이어는 상담 유형 변경 시 조정한다.
3. 학습 레이어는 평가 주기마다 업데이트한다.

## 왜 이 구조가 필요한가

프롬프트의 대부분 문제는 "모든 규칙을 한 본문에 누적"하기 때문에 생긴다.
레이어를 분리하면 다음이 가능해진다.

1. 어떤 변경이 품질에 영향을 줬는지 추적 가능
2. 상담 유형별 템플릿 재사용 가능
3. 고객 피드백의 정책화 여부를 구분 가능
4. 모델 교체 시 고정 규칙을 유지한 채 비교 가능

## 권장 적용 방식

실행 시에는 아래 순서로 조립한다.

1. 고정 레이어 로드
2. 상담 유형에 맞는 가변 레이어 로드
3. 최신 학습 레이어 로드
4. 세 레이어를 합쳐 최종 실행 프롬프트 생성

즉, 최종 프롬프트는 저장하는 문서라기보다 조립 결과물에 가깝다.
