# STT 정제 레이어 설계

## 목적

현재 요약 품질 병목이 모델 자체보다 STT 입력 품질에 있다면,
프롬프트를 더 세게 쓰는 것보다 먼저 STT 정제 레이어를 넣어야 한다.

이 레이어의 목표는 3가지다.

1. 요약 전에 업무 무관 노이즈를 줄인다.
2. 불확실한 토큰을 확정하지 않고 보류한다.
3. 원문과 정제본의 역할을 분리해 모델 오판을 줄인다.

## 문제 정의

반복 오류는 크게 아래 두 유형으로 묶인다.

1. 정상 STT 과다 반영
2. 핵심 정보 누락

원문을 그대로 넣으면 모델은 중요하지 않은 숫자, 본인확인 발화, 반복 멘트, 혼입 문장을 자연스럽게 정리해서 넣으려 하고, 그 과정에서 고객 요청, 처리 상태, 후속조치가 밀린다.

## 권장 처리 흐름

1. 원문 STT 수집
2. 기계적 정제
3. 불확실 구간 표시
4. 핵심 슬롯 추출
5. 요약 모델 입력 생성
6. 원문 기준 재검증

## 1. 기계적 정제

우선 규칙 기반으로 제거 가능한 노이즈를 줄인다.

- 반복 인사말
- 네/아/잠시만요 같은 채움 발화
- 본인확인용 개인정보
- 업무와 무관한 상세 시각
- 동일 의미 반복 문장

## 2. 불확실 구간 표시

아래 항목은 섣불리 보정하지 말고 `uncertain_spans`로 남긴다.

- 발음이 비슷한 상품명
- 여러 후보가 가능한 숫자
- 다른 상담이 혼입된 것으로 보이는 문장
- 상담 목적과 직접 연결되지 않는 코드값

원칙은 `모르면 맞히지 말고 보류`다.

## 3. 핵심 슬롯 추출

정제 후에는 아래 슬롯을 우선 뽑는다.

- 고객 요청 사항
- 계약/대상 관계
- 처리 상태
- 상담사 후속조치
- 기한/긴급성
- 민원/불만

이 슬롯들이 먼저 잡혀야 요약이 배경 설명에 끌려가지 않는다.

## 4. 입력 구조 권장안

```json
{
  "source": {
    "source_text": "원문",
    "source_text_cleaned": "정제본"
  },
  "stt_preprocess": {
    "cleanup_applied": [],
    "uncertain_spans": [],
    "noise_patterns": [],
    "retained_key_facts": []
  }
}
```

## 프롬프트 적용 원칙

1. 핵심 정보 추출은 `source.source_text_cleaned` 우선
2. 최종 사실 확인은 `source.source_text` 우선
3. `uncertain_spans`는 요약에서 확정 서술 금지
4. `cleanup_applied`에 포함된 항목은 재등장시키지 않음

## 기대 효과

- 개인정보, 세부 숫자, 혼입 문장 과다 반영 감소
- 고객 요청과 처리 상태 누락 감소
- Qwen 계열에서 잦은 자연스러운 오보정 감소
- 후속조치 항목 보존율 상승

## 운영 메모

정제 레이어는 요약 모델을 대체하지 않는다. 역할은 요약 모델이 실수하기 쉬운 입력을 덜 위험한 형태로 바꾸는 것이다. 지금 병목이 STT 노이즈라면, 프롬프트 튜닝만 반복하는 것보다 이 레이어를 먼저 넣는 편이 효율이 높다.
