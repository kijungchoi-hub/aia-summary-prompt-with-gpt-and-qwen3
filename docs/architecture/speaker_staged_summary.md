# 발화자 단계형 요약 설계

## 목적

`OPTIMIZATION_2.md`에서 제안한 방식처럼,
전체 대화를 한 번에 바로 요약하지 않고 화자별 중간 구조화를 거쳐 최종 요약으로 가는 절차를 표준 요약 프로세스로 정의한다.

이 방식의 목적은 아래와 같다.

1. 고객 요청과 상담사 안내가 섞이는 문제를 줄인다.
2. 멀티턴 대화에서 누락과 역할 혼동을 줄인다.
3. 후속조치와 처리 상태를 별도 축으로 안정적으로 남긴다.

## 권장 프로세스

```text
STT 전사
-> 화자 분리
-> 문장 분할
-> 발화자별 문장 정리
-> 고객 요약
-> 상담사 요약
-> 최종 통합 요약
```

## 내부 처리 규칙

1. 고객 발화에서는 문의 목적, 요청 사항, 우려 사항, 핵심 질문을 우선 추출한다.
2. 상담사 발화에서는 안내 내용, 필요 서류, 조건/제한, 후속 조치를 우선 추출한다.
3. 최종 요약에서는 고객 요구와 상담사 안내를 섞지 않는다.
4. 처리 상태와 후속 조치는 최종 통합 단계에서 다시 한 번 검증한다.

## 권장 출력 구조

```text
[상담요약]
- 고객 요청 사항:
- 계약/대상 관계:
- 핵심 상황:
- 민원/불만:
- 처리 상태:
- 상담사 후속조치:
- 기한/긴급성:
- 특이사항:
```

## 단계별 품질 체크

### 1. 고객 요약

- 문의 목적이 남았는가
- 확인하려는 핵심 질문이 남았는가
- 불만/우려가 있으면 누락되지 않았는가

### 2. 상담사 요약

- 안내 내용이 남았는가
- 필요한 서류 또는 조건이 남았는가
- 후속 조치가 남았는가

### 3. 최종 통합 요약

- 고객 발화와 상담사 발화가 섞이지 않았는가
- 처리 상태가 보존되었는가
- 후속 조치가 누락되지 않았는가

## 적용 원칙

1. 화자 정보가 있으면 반드시 발화자 단계형 요약을 우선 사용한다.
2. 화자 정보가 약해도, 가능한 범위에서 고객 발화와 상담사 발화를 분리해 중간 요약을 만든다.
3. 짧은 대화는 발화자별 원문 묶음 기반 요약으로, 긴 대화는 문장 단위 정리 후 묶음 요약으로 처리한다.
4. Qwen3.5 계열은 멀티턴 안정화를 위해 이 절차를 기본 경로로 사용한다.
